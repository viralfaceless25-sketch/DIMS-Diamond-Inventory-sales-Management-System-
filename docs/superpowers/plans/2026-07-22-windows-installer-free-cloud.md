# Diamond Inventory Windows Installer and Free Cloud Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish Maitri Diamond Inventory on free cloud services and deliver `DiamondInventory-Setup-1.0.0.exe`, which runs on a new Windows 10/11 computer without local development tools or configuration.

**Architecture:** Render serves an exported Next.js frontend from its static CDN and runs the Express/Socket.io API on a sleeping Free web instance. Supabase remains the shared Postgres database. A capability-free Tauri 2 shell opens the HTTPS frontend in WebView2; an NSIS installer handles shortcuts and the WebView2 bootstrapper.

**Tech Stack:** Next.js 14 static export, React 18, Express 4, Socket.io 4, Supabase Postgres, Render Blueprint, Tauri 2, Rust, NSIS, PowerShell, Node test runner.

## Global Constraints

- The initial installer filename is exactly `DiamondInventory-Setup-1.0.0.exe`.
- Staff install one file and do not install Node.js, Rust, configure `.env`, or enter a URL.
- Windows 10 and Windows 11 with internet access are supported.
- The desktop shell exposes no Tauri filesystem, shell, process, updater, or database capability to remote content.
- All production traffic uses HTTPS; no secret is committed or bundled.
- Render API plan and Supabase plan cost $0 initially; API cold starts are accepted.
- Existing authentication, roles, stock, request, transfer, upload, label, and realtime behavior must remain intact.
- Writes are never automatically replayed after ambiguous network failures.
- The unsigned first release may show Windows SmartScreen.

```ts
// frontend/src/lib/readiness.ts
export interface ReadinessOptions {
  fetcher?: typeof fetch;
  sleep?: (ms: number) => Promise<void>;
  now?: () => number;
  timeoutMs?: number;
  intervalMs?: number;
}

export async function waitForApiReady(apiUrl: string, options: ReadinessOptions = {}) {
  const fetcher = options.fetcher ?? fetch;
  const sleep = options.sleep ?? ((ms) => new Promise((resolve) => setTimeout(resolve, ms)));
  const now = options.now ?? Date.now;
  const timeoutMs = options.timeoutMs ?? 90_000;
  const intervalMs = options.intervalMs ?? 2_000;
  const deadline = now() + timeoutMs;
  while (now() < deadline) {
    try {
      if ((await fetcher(`${apiUrl}/ready`, { cache: 'no-store' })).ok) return 'ready' as const;
    } catch { /* sleeping or temporarily unreachable */ }
    await sleep(intervalMs);
  }
  return 'timeout' as const;
}
```
